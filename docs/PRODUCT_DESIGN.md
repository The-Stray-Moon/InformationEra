# Information Era — 产品设计文档

> 版本 v1.0（2026-09-05）｜状态：设计定稿，待开发
> 模组：Information Era（`cc.sighs.informationera`）｜加载器优先级：NeoForge 1.21.1
> 依赖：ApricityUI 1.2.4（`com.sighs:ApricityUI-neoforge-1.21.1`）

---

## 1. 背景与愿景

在 Minecraft 中实现一个"信息时代"的文件资源管理器：把**物品当作文件**管理。

- 每位玩家拥有一块容量**无限**的"个人磁盘"（服务端权威存储），用文件夹整理物品库存；
- 界面复刻 Windows 文件资源管理器：导航树、大图标/小图标/列表/详细信息四种视图、工具栏、搜索、排序、右键菜单、多选、拖拽；
- 在**所有容器界面**（背包、箱子、机器等）上都绘制一个可随时展开的悬浮入口（overlay），支持拖拽**输入/输出**物品；
- 拥有完整的弹窗管理体系：确认、输入、重命名、批量进度、属性查看等。

### 一句话定位

> 每个玩家自己的"物品网盘"，用文件管理器的交互方式来组织无限容量的库存。

## 2. 目标与非目标

### 2.1 目标（v1.0）

- [x] 每玩家独立的无限容量存储（世界级 saveddata，按玩家 UUID 分片）
- [x] 一个文件 = 一种物品（id + NBT）+ 任意数量（堆叠无上限）
- [x] 文件夹无限层级组织；新建/重命名/删除/移动/复制
- [x] 四种视图布局 + 搜索 + 排序 + 筛选
- [x] 容器界面悬浮入口 + 面板内双区拖拽输入/输出
- [x] 回收站（可恢复、可彻底删除、可自动清理）
- [x] 统一弹窗管理体系
- [x] 中文 / 英文界面

### 2.2 非目标（明确不做，含后续版本）

- 共享盘 / 多人权限系统（v1.1 候选）
- 自动化管道（AE 风格的网络传输，预留接口但不实现）
- 合成预览、自动化合成
- 跨服务器云同步 / 物品打包导出导入（v1.1 候选）
- 玩家 NBT 存储（避免玩家存档膨胀，选用世界 saveddata）

## 3. 核心概念

| 概念 | 定义 |
| --- | --- |
| 物品文件（Item File） | 最小存储单元：`(物品 id, NBT, 数量, 所属文件夹, 元信息)`。数量为任意非负整数，突破原版 1–64 堆叠与 NBT `Count` byte(127) 限制。 |
| 文件夹（Folder） | 可嵌套的容器，持有文件与子文件夹；有自己的名称、创建/修改时间。深层级上限 64，防环（按 id 引用，不允许父指回子）。 |
| 磁盘（Disk） | 一个玩家全部存储的根，含文件夹树、回收站、个人偏好。 |
| 回收站（Recycle Bin） | 磁盘内置的特殊文件夹；删除的文件带"原路径 + 删除时间"进入，可恢复或彻底删除。 |
| 视图（View） | 大图标 / 小图标 / 列表 / 详细信息，纯 CSS 布局，与存储无关。 |
| 入口（Entry） | 容器界面上的悬浮按钮与快捷面板（Overlay），负责输入/输出物品。 |

### 3.1 与真实文件的对应

| Windows 概念 | Information Era 对应 |
| --- | --- |
| 文件 | 物品文件（一个物品类型 + 数量） |
| 文件夹 | 文件夹 |
| 此电脑 / 磁盘根 | 个人磁盘（默认名"信息磁盘"，玩家可改名） |
| 回收站 | 回收站 |
| 快速访问（最近使用/收藏） | 快捷区：最近使用、收藏夹 |
| 属性 | 文件属性面板（id、数量、NBT 概要、路径、时间） |

## 4. 总体架构

### 4.1 分层（沿用 common + targets 结构）

```
common/                          ← 纯 Java：存储、服务端逻辑、网络包定义、DTO、页面资源
  src/main/resources/assets/apricityui/apricity/
    screens/explorer.html        资源管理器主界面
    overlays/entry.html          容器悬浮入口与快捷面板
    themes/ie/…                  信息时代主题扩展 CSS（基于 Ore 主题变量覆盖）
  src/main/resources/assets/informationera/textures/gui/…   自家贴图（<texture> 用）
targets/neoforge-1.21.1/         ← 加载器适配：入口、事件挂接、AUI 初始化、菜单/容器联动
```

- 所有 AUI 页面按规则放入 `assets/apricityui/apricity/` 逻辑根（构建时该目录自动合并进 jar）；
- 自家贴图放 `assets/informationera/`，页面里用 `<texture src="informationera:textures/gui/xxx.png">` 引用；
- **本设计不依赖 MC 菜单槽位**：资源管理器是"虚拟库存浏览器"（纯 DOM 渲染），不是容器。因此不受 256 槽同步限制，容量设计上是无限的。

### 4.2 模块职责

| 模块 | 职责 |
| --- | --- |
| `storage` | 磁盘数据模型、saveddata 读写、懒加载、增量保存、校验 |
| `service` | 转移/移动/删除/回收等业务规则（服务端权威，全部在此执行） |
| `network` | `@NetworkPacket` 定义、编解码、C2S/S2C 协议、chunk 大包 |
| `ui` | AUI 页面驱动的 Java 桥接：`<item>` 驱动、tooltip、拖拽落点计算 |
| `platform`（target） | NeoForge 事件（ScreenOpen）、键位、AUI `scanPackage`、jarJar 打包 |

### 4.3 数据流

```
[玩家操作 HTML] → [页面 JS / Java 桥] → [C2S 网络包] → [server service 校验+执行] → [S2C 响应]
                                                    ↓
                                         saveddata（磁盘持久化）
```

所有变更**只在服务端执行**；客户端只读镜像（当前文件夹条目、容器槽快照、进行中的拖拽状态）。

## 5. 数据模型

### 5.1 存储位置

- 世界级 `SavedData`（主世界维度），键名 `informationera_data`；
- 内部按玩家 UUID 分片：`players: { uuid: Disk }`；
- 理由：随存档走、服务器权威、不受玩家.dat 膨胀影响、多 Mod 协作时可复用。

### 5.2 NBT 结构（草案）

```text
InformationEraData (SavedData)
├── version: int
└── players: {
      "<uuid>": {
        name: string,
        folders: [           // 扁平的文件夹表，parent 指向
          { id: "f_<ulid>", name, parent: "f_..." | "", order: int,
            createdAt, updatedAt }
        ],
        files: {             // 按文件夹聚合 → 分页友好
          "f_<ulid>": [      // 根目录用 "" 键
            { id: "fl_<ulid>", item: "<ns>:<path>", tag: <nbt>, count: long,
              customName?: string, createdAt, updatedAt }
          ]
        },
        recycle: [
          { id, item, tag, count, customName?, originFolder, deletedAt }
        ],
        favorites: [fileId],        // 收藏
        recent: [{ fileId, lastAt }],  // 最近使用（上限 100）
        prefs: { sortMode, viewMode, expandEntry, ... }
      }
    }
```

### 5.3 关键设计点

- **数量突破限制**：数量存 `long`，不写进 `ItemStack.Count`（NBT byte 上限 127）。展示时构造临时 ItemStack 驱动 `<item>`（clamp 到 127），数量角标/排序用真实 count；**输出到外界时按目标槽上限拆分**（原版最大堆叠 64，不可堆叠物品每次 1）。
- **id 稳定**：文件/文件夹用 ULID，重命名/移动不改变 id → 收藏、最近记录、引用不失效。
- **合并规则**：输入时若目标文件夹已存在"同 id + 同 NBT（忽略数量）"的文件 → 数量并入；否则新建文件。开关见设置。
- **容量**：存储层无限；`long` 计数、每文件夹条目数无硬上限（界面分页 200/页 + 虚拟滚动）。

### 5.4 性能与持久化

- 玩家磁盘**懒加载**：首次请求时从磁盘读入并缓存，离开服务端或闲置 10 分钟释放；
- **增量保存**：变更仅标记所属玩家 dirty，服务端 `tick` 末统一保存一次；服务器停止/存档时 flush；
- 大包分块：网络响应超过阈值用 AUI `chunkThreshold` 自动分块；
- DOM 更新批量化（`beginAttributeBatch` / `endAttributeBatch`），禁止逐帧整页 `refresh()`。

## 6. 网络协议（C2S/S2C）

沿用 AUI 网络层：自定义包实现 `INetworkPacket<T> & CustomPacketPayload`，标注 `@NetworkPacket(modId="informationera", id=..., side=..., priority=..., chunkThreshold=...)`，包注册进 AUI 自动扫描或 mod 自身注册。

| 包 | 方向 | 说明 |
| --- | --- | --- |
| `OpenDiskRequest` | C2S | 打开磁盘，服务端返回树结构 + 根目录条目 |
| `FolderReadRequest/Response` | C2S/S2C | 分页读取某文件夹的文件/子文件夹列表（含数量、排序） |
| `FolderCudRequest` | C2S | 新建 / 重命名 / 移动 / 删除文件夹 |
| `FileCudRequest` | C2S | 重命名 / 移动 / 复制 / 删除文件（多选批量） |
| `TransferRequest` | C2S | 物品转移（详见 7.3），服务端全量校验后执行 |
| `RecycleRequest` | C2S | 恢复 / 彻底删除 / 清空回收站 |
| `ContainerMirrorSync` | S2C | 打开容器时同步容器槽快照（客户端渲染镜像区） |
| `OpResult` | S2C | 成功 / 失败原因（权限、重复、数量非法、目标已损坏等）→ Toast |

所有 C2S 包附 `player.getServer()` 线程上下文；服务端二次校验：UUID 归属、计数非负、文件夹存在、深度、容器 `stillValid`、槽位 `mayPickup/mayPlace` 语义。

## 7. 界面与交互设计

### 7.1 资源管理器主界面（Screen，`screens/explorer.html`）

打开方式：键位（默认 `Y`，可改绑定），或从悬浮入口"打开完整资源管理器"。`aui-viewport: mode=browser` + `aui-mouse-events: intercept`。

```
┌──────────────────────────────────────────────────────────────────┐
│ [←][→][↑] 面包屑: 信息磁盘 ▸ 矿物 ▸ 铁  [🔍 搜索…] [视图▾] [≡]   │ 命令栏
├───────────┬──────────────────────────────────────────────────────┤
│ 导航树      │  排序▾ 筛选▾（模组/类型/稀有度/标签）               │
│ ▸ 快速访问  │                                                    │
│   ▸ 最近使用 │  ┌─ 大图标网格（虚拟滚动）──────────────┐          │
│   ▸ 收藏    │  │ ◻[铁矿]  ◻[煤矿]  ◻[文件夹:工具]      │          │
│ ▸ 信息磁盘  │  │  1234     567        (子项)           │          │
│   ▸ 矿物    │  │ ◻[绿宝石] ◻[金锭]                    │          │
│   ▸ 工具    │  └──────────────────────────────────────┘          │
│ ▸ 回收站    │                                                    │
├───────────┴──────────────────────────────────────────────────────┤
│ 状态栏: 12 项 | 已选 3 项（2,058 个物品）| 磁盘共 128 文件夹       │
└──────────────────────────────────────────────────────────────────┘
```

- **视图切换**：大图标（96px）/ 小图标（48px）/ 列表（图标+名称）/ 详细信息（名称、数量、类型、模组、稀有度、修改时间），快捷键 Ctrl+1/2/3/4；每个文件夹记忆上次视图。
- **文件夹图标**：自绘 `<svg>` 或 `<texture>`；物品图标用 `<item>` 元素由 Java `setDrivenState(stack, ...)` 驱动（含数量角标、tooltip 走 `renderTooltip`）。
- **选择**：单击选中、Ctrl 多选、Shift 范围、框选（拖拽空白区拉选区）；选中态/悬停态 CSS。
- **排序**：名称（自然顺序）/ 数量 / 创建时间 / 修改时间 / 稀有度，升/降序；文件夹恒在文件上方（设置可关）。
- **分组**：单层分组，依据包括名称、修改/创建日期、类型、数量、作者、来源模组、稀有度、当前耐久状态、实际堆叠上限、附魔状态和真实父文件夹；组序可反向，组内排序独立。先筛选/去重再分组，组头显示当前结果条目数，折叠只在本次会话保留；依据与组序按文件夹保存。
- **搜索框**：输入即时过滤当前文件夹；空结果提示"上移到全盘搜索"按钮（走服务端模糊查询，按名称/显示名/id/标签）。
- **右键菜单**：空白处（新建文件夹 / 粘贴 / 排序 / 视图 / 刷新）；文件（打开 / 在新标签预览？→ v1.1 / 剪切 / 复制 / 删除 / 重命名 / 移到回收站 / 属性）；文件夹（打开 / 剪切 / 复制 / 重命名 / 删除 / 属性）。
- **快捷操作**：双击/Enter 打开；F2 重命名；Delete 删除（进回收站）、Shift+Delete 彻底删除；Ctrl+C/X/V、Ctrl+A；Ctrl+F 聚焦搜索；Backspace/Alt+← 返回上级；F5 刷新。
- **拖拽（盘内）**：拖动（单选/多选）到导航树文件夹 = 移动；Ctrl+拖 = 复制；拖到回收站 = 删除；拖到面包屑/地址栏目标 = 移动至该文件夹。拖拽过程显示幽灵卡片 + 落点高亮。

### 7.2 容器悬浮入口（Overlay，`overlays/entry.html`）

- 任何容器 Screen（背包、箱子、机器、ApricityContainerScreen）打开时，右下角出现**悬浮按钮**（可拖动，记忆位置，半透明，不拦截非按钮区域点击 —— `pointer-events: none` + 按钮区域 `auto`）。
- 点击按钮**展开快捷面板**，再点收起；`Esc` 收起。
- Overlay 用持久文档（`setReloadPersistent(true)` + `translateZ` 置顶）绘制在容器界面上层；输入拦截只落在按钮/面板命中区域（`aui-mouse-events: intercept` 是整页开关，命中区域拦截按 hit region 生效 —— 实现时按钮与面板为可命中区域，其余被剪裁区域不拦截）。
- **技术备选**：若 Overlay 跨 Screen 置顶/输入存在兼容问题，退回方案 B —— 对 `AbstractContainerScreen` 渲染做 mixin，在 screen 坐标系内绘制按钮（JEI 同款思路），面板本体仍是 AUI 页面。M1 阶段优先验证方案 A。

```
快捷面板布局（单 Document：拖拽必须限制在同一个 Document 内）
┌──────────────────────────────┐
│ [容器名]        [打开完整管理器]│
│ 容器区（当前容器槽位镜像网格）  │
│   ◻ ◻ ◻ ◻ ◻ ◻               │
│   ◻ ◻ ◻ ◻ ◻ ◻               │
│ ─────────────────────────── │
│ 磁盘快捷区（最近使用 / 收藏 /   │
│ 当前打开文件夹 / 回收站）       │
│   ◻ ◻ ◻ ◻                   │
│ [🔍 搜索…]  [收进全部▾]        │
└──────────────────────────────┘
```

- 容器镜像由客户端从当前 `screen.menu.slots` 快照渲染（槽内容、空槽、禁用态灰显），随容器内容变化刷新；不额外请求服务器。
- "收进全部"：一键把当前容器（或按条件筛选出的物品）输入磁盘。

### 7.3 物品输入/输出（拖拽式）

**均在快捷面板这一个 Document 内完成**（跨 Document 拖拽 AUI 不支持，故不在面板与主界面之间拖拽；主界面内拖拽自洽）。

| 操作 | 手势 | 语义 |
| --- | --- | --- |
| 输出 | 磁盘快捷区文件 → 拖到容器区某槽 | 从磁盘取出，按目标槽上限拆分后放入该槽（放不下则放不下部分留在磁盘并 Toast 提示） |
| 输出（批量） | 磁盘多选 → 拖到容器区 | 依次填满容器可用槽（不可堆叠物一槽一件） |
| 输入 | 容器区某槽 → 拖到磁盘快捷区/文件夹 | 槽内物品移入磁盘：目标文件夹已含同物品则并入，否则新建文件；槽位清空 |
| 输入（批量） | 容器区多选/框选 → 拖到磁盘区 | 全部输入，按合并规则入库 |
| 快速整理 | "收进全部▾" | 收进全部 / 收进相同物品 / 收进当前筛选条件匹配物品 |

- 拖拽源与落点均有高亮与"允许/禁止"光标反馈；
- **一切转移由服务端 `TransferRequest` 执行**：客户端只描述意图（源磁盘文件、目标槽序，或源槽序、目标文件夹 id），服务端校验后原子执行（先扣减后附加，同 tick 完成，失败回滚并返回 `OpResult`）；
- 容器槽遵循原版规则：不可插入/不可取出的槽在镜像中灰显，禁止作为拖拽目标/源；
- 输入时若磁盘同名文件夹冲突？不存在 —— 文件夹 id 唯一，移动只改 parent，不涉及重名。

### 7.4 弹窗管理体系（ModalManager）

统一弹窗层，包装并约束 AUI `DialogWindow`：

- **层级与焦点**：弹窗栈式管理，后开者置顶；遮罩随层级加深（默认 0.35 黑）；焦点钳制在最顶弹窗内（Tab 循环），关闭后焦点回到调用者；
- **Esc 语义**：Esc 关最顶弹窗；有确认框未确认时 Esc = 取消；
- **组件清单**：
  - 确认框（删除文件夹、彻底删除、清空回收站、收进全部大额操作）
  - 输入框（新建文件夹、重命名文件/文件夹；预填旧名并全选）
  - 进度框（批量转移/彻底删除：进度条、可取消、完成/失败摘要）
  - 属性框（文件属性：物品、数量、模组、稀有度、路径、创建/修改时间；文件夹属性：子项数、总数量）
  - 右键菜单（`ContextMenu`）、Tooltip、Toast（`ToastManager` 或自有主题化 toast）
- **位置**：默认居中，标题栏可拖动，记忆最近位置；缩放页面（`mode=browser`）下坐标一律用 Document 逻辑坐标。

### 7.5 回收站交互

- 入口在导航树；删除 → 进回收站（记录原路径 + 删除时间），文件数在树中显示；
- 回收站内：恢复（回原文件夹，若原文件夹已不存在则回根）、彻底删除（确认框）、清空（确认框）；
- 自动清理：默认保留 30 天，可设置关闭；被自动清理的不可恢复（日志记录）。

| 回收站 | 保留天数 / 关闭自动清理 | 30 天 |
| 视图 | 默认视图、排序方式、文件夹置顶 | 大图标 / 名称 / 开 |
| 分组 | 分组依据、组序方向 | 无 / 正向 |
| 入口 | 悬浮按钮位置记忆、透明度、总是展开 | 开 / 70% / 关 |
| 键位 | 打开资源管理器 | Y |

## 9. 安全与防作弊

- 服务端权威：一切变更经 `service` 校验执行，客户端只读；
- 不提供创造物品：磁盘内物品只能来自玩家物品栏/容器；
- 防重复发放：转移原子化（源扣减与目标附加同 tick，失败回滚）；
- 输入数量合法性：`count >= 0`、`<= long`、目标槽容量匹配；
- 权限：默认所有玩家可用自己的磁盘；不做 OP 限制（联机服规则 v1.1 可加）；
- 禁止通过改 DOM/发包越权：文件夹归属、容器 `stillValid` 服务端校验。

---

## 10. 性能设计

- 虚拟滚动：大图标/列表仅渲染可视区行（行高固定、`content-visibility` 等价方案）；
- 分页：文件夹读取 200 条/页，滚动加载；
- 缓存：磁盘内存缓存（懒加载/闲置释放）、条目 DTO 缓存；
- 批量 DOM 更新（`beginAttributeBatch`），避免逐帧刷新；
- 详情视图像素级对齐：图标统一走 `<item>` + 图标缓存，不做每帧重建；
- 大磁盘（>10 万条目）：文件夹表 + 文件表分离存储、索引（按文件夹/按更新时间）为 v1.1 优化项。

## 13. 技术风险与备选方案

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 持久 Overlay 在容器 Screen 上的置顶/输入 z-order 行为不确定 | 入口不可见或抢事件 | M1 早期验证；备选方案 B：`AbstractContainerScreen` 渲染 mixin（JEI 式按钮） |
| `ItemStack.Count` 为 byte，展示/交互受 127 限制 | 大数量角标/tooltip 错误 | 存储用 long；展示 clamp；拆分输出；角标自绘 |
| 磁盘条目巨大导致 NBT 体积与存档卡顿 | 保存慢、网络包大 | 懒加载 + 分片/增量保存 + 分页 + chunk 分包；索引化 v1.1 |
| 原版容器部分槽位语义（不可插/不可取）复杂 | 转移失败或被拒 | 服务端严格按槽语义校验；镜像灰显；OpResult 反馈 |
| AUI API 演进（1.2.4 → 更高）导致适配层变动 | 构建/功能回归 | pin 版本；跨版本适配层集中在 target 与 ui 桥 |
| 跨 Document 拖拽不支持 | 面板与主页无法直接拖拽物品 | 交互全部收敛在单一 Document 内（面板内拖拽；主页内拖拽） |

## 14. 未决问题（进入开发后逐项确认）

1. 磁盘命名与图标风格（资源管理器"此电脑"的对应物）；
2. 文件"打开"动作的落点：v1 内只有预览/属性，还是预留"点击物品打开所属模组文档"；
3. 多选整体拖入容器时无空格地的反馈强度（Toast / 落点禁止图标）；
4. 联机服权限扩展（白名单、限额、共享盘）—— v1.1 再议；
5. 是否提供 `/ie` 前缀的管理命令（查看玩家磁盘占用、清理孤儿数据）—— 建议 v1.1 做；
6. 跨版本铺开顺序：fabric-1.20.1 → forge-1.20.1 → neoforge-26.1；
7. 大数量合并时数值显示精度（>10^9 显示"1.2亿"式缩写）。
